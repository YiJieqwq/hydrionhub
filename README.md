# HydrionHub · 氢离子

HydrionHub 是用 Kotlin 和 Jetpack Compose 编写的 Android 多模型客户端。0.1.6 恢复版保留了 0.1.5 的 DeepSeek 对话功能，并恢复了悬浮顶栏和输入框。默认模型是本机 Hydrion。恢复版使用独立包名 `io.hydrion.hub.reconstructed`，可以与原应用并排安装，两者分别保存聊天记录。

## 使用 DeepSeek

在「设置 → 聊天模型 → DeepSeek」输入 API Key 并保存，然后在聊天输入框的模型选择器里选 DeepSeek。密钥只在本次运行中保留。Flash 支持文字和图片，V4 Pro 支持文字。对话通过 HTTPS 请求 `/responses`，可查看流式思考和正文。停止生成会保留已收到的内容，重新生成历史回复会沿用该条回复的模型。

在线对话按当前会话、供应商和模型取最近一次已结束请求的用量。优先使用接口报告的总数；仅在输入和输出计数都存在时才可相加。用量缺失时显示未知。DeepSeek 的上下文窗口默认是 1,000,000 tokens，可在对应模型的「编辑模型 → 基础 → 上下文窗口」修改。DeepSeek 蓝鲸图标来自 Lobe Icons，MIT 许可随应用附带。[Lobe Icons](https://github.com/lobehub/lobe-icons)

## 聊天协议

在「设置 → 聊天模型」添加供应商，填写协议、Base URL 和本次运行使用的 API Key。在「模型」页添加账号可调用的模型 ID，然后从聊天输入框选择它。图片输入还需要模型本身支持视觉，并在模型配置中启用。

| 供应商协议字段 | 传输 | 服务地址 |
| --- | --- | --- |
| `OpenAI Chat Completions` | HTTP POST，SSE | OpenAI、DeepSeek 或明确支持该协议的 HTTPS 服务 |
| `OpenAI Responses` | HTTP POST，SSE | OpenAI、DeepSeek 或明确支持该协议的 HTTPS 服务 |
| `OpenAI Responses WebSocket` | WebSocket，每轮一次 `response.create` | 仅 OpenAI 官方 `wss://api.openai.com/v1/responses` |

OpenAI 的 Base URL 可填 `https://api.openai.com/v1`，DeepSeek 可填 `https://api.deepseek.com`。三种协议都使用本机保存的可见历史。WebSocket 每轮新建连接，断线保留已收到的内容，由用户决定是否重试。手动重试沿用原供应商、模型和协议。服务端报告的输入、输出、总用量以及可用的缓存和推理计数分别保存，缺失项保持未知。

默认模型、当前选择和参数按供应商 ID 与模型 ID 一起保存。升级旧配置时，同名模型按旧选择器的顺序匹配一次。内置 DeepSeek 使用 Responses HTTP。若要用 DeepSeek 的 Chat Completions，可以另建聊天供应商，使用同一官方地址并在该供应商下填写 API Key。

## 聊天正文图表

需要数据图时，可以请助手返回标为 `chart` 的代码块。下面的例子会显示两个系列的散点图，点的位置取自各自的 X 和 Y。消息内可切换到数据表，也可将同一组数据导出为 CSV。

~~~chart
{"style":"scatter","title":"花园观测","x_axis":{"title":"小时"},"y_axis":{"title":"高度"},"series":[{"name":"薄荷","points":[{"x":1,"y":4},{"x":3,"y":7},{"x":10,"y":5}]},{"name":"紫苏","points":[{"x":2,"y":3},{"x":9,"y":6}]}]}
~~~

`line` 和 `bar` 支持数值坐标点，也支持 `x_axis.data` 中的共同类目或数值配合每个系列的等长 `values` 数组。每个系列可选 `#RRGGBB` 颜色。单图最多 8 个系列，每系列最多 256 个点。单条回复最多渲染 8 张图、合计 1,024 个点。回复结束后渲染，未闭合、无效或超限的图表保留源码供复制。

## 使用 OpenAI 图像生成

在「设置 → 图像生成模型」新建供应商，协议填 `OpenAI Images`，Base URL 填 `https://api.openai.com/v1`。输入本次运行的 API Key，添加账号可用的 GPT 图像模型 ID，例如 `gpt-image-1.5`，并在 Image 的 Configure 中选择它。保留默认请求模板即可。若自定义模板，在线生成要求原样使用提示词和所选模型 ID。[OpenAI 图像生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate/)

Image 模式和本机聊天中已启用的图片生成操作使用同一个图像供应商。在线入口接受文字提示，每次最多 4 张，受模型预算约束。返回的 PNG 保存在应用私有目录，历史预览、导出、复制和聊天视觉输入均读取这份文件。图像编辑与参考图生成尚未接入。官方请求失败会显示错误，手动重试沿用原模型。中止会关闭客户端连接，已送达的请求可能仍在服务端运行。

内置本机图片模型继续生成示例图。其他纯本地图片供应商可以填写 `local` 协议并留空服务地址。

## PRoot 环境后端

每个环境引用一个容器和一个应用私有工作区。多个环境可以共用工作区，并分别指定 `/workspace` 下的工作目录。首版最多登记一个新容器。会话可以保存预配置环境的 ID，旧会话默认未绑定。

每次规划命令都会检查预置的 PRoot、加载器、受信镜像的安装收据及目录结构，再核对镜像内可执行文件和工作目录。规划结果保存逐项参数，只绑定登记的工作区，宿主环境变量不随命令传入。每次规划分配独立实例，取消和收取退出码的接口只接受该实例拥有的直接子进程句柄。

当前实现止于命令规划和生命周期接口。设备启动还需要经验证的 Android 加载器、rootfs 和实际进程实现。运行时的权限取自宿主应用，PRoot 本身不提供运行不受信任代码所需的隔离。

## 运行

需要 JDK 17、Android SDK Platform 35 和 Android SDK Build-Tools 34.0.0。安装目标为 Android 8.0（API 26）及以上。

```sh
./gradlew assembleDebug testDebugUnitTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

接入设备后，可运行 `./gradlew :app:connectedDebugAndroidTest` 执行 Compose 界面冒烟测试和 PNG 导出测试。

## 试用

1. 启动后可在顶部选择 Chat 或 Image。点输入框开始编辑，工具栏随之展开。收起软键盘后，有文字或附件的草稿保留工具栏。输入一条消息并发送，当前会话即进入历史，模式随之锁定。
2. 在 Chat 发送「写一段 Kotlin 代码」可查看流式回复、思考和代码块。点回复上方的「思考过程」可展开模拟思考记录。回复下方可直接复制或重新生成，用户消息旁可复制、编辑。用「搜索」或「画一幅」开头试用两个模拟工具。在生成期间可停止，输入 `/error` 可试验失败和重新生成。
3. 在 Image 打开 Configure，选择张数和尺寸后发送提示词。可翻看缩略图、查看大图、保存、复制或将某张图加入下一条请求作为参考。
4. 打开侧栏可搜索、切换、置顶、重命名或删除会话。侧栏底部的设置可管理语言和图片供应商。在「配置」页修改名称、启用状态、地址和 API Key，在「模型」页手动添加模型或搜索本地示例目录。两个页签共用草稿，点击顶部「保存」后生效。API Key 仅在本次运行中保留。
5. 模型可分别声明支持的能力，Configure 会据此显示选项。图片生成由图像生成模型配置，支持 JSON 请求体、模板变量和本地预览。
6. 打开「设置 → 消息样式」可切换纯色、磨砂玻璃和主题默认样式。选择浅色或深色，再选用户或助手，可分别修改背景、边框和文字颜色。预览和已有会话使用同一套渲染，设置实时保存。助手正文气泡默认关闭。
7. 在「供应商 → 模型」点击一个模型，进入基础、推理和高级编辑页。顶部勾选择保留这次模型编辑，返回供应商后再点「保存」写入。模型的请求 ID 和显示名可分别修改。Chat 与 Image 按模型类型选用，Embedding 仅供配置。
8. 当前会话标题可点按重命名。右上角更多菜单中的查找支持上一处、下一处和命中高亮。

## 页面与状态

| 入口或组件 | 源码目录 | 职责 |
| --- | --- | --- |
| 原生 Activity、共享界面 | `app/src/main/java/io/hydrion/hub/ui` | 主界面组装顶栏、内容、输入框及弹层，统一处理窗口和输入法边距 |
| 顶栏与侧栏 | `ui/chrome`、`ui/sidebar` | 空会话模式选择、会话信息、全文查找和历史管理 |
| 输入框 | `ui/composer` | 折叠与编辑状态、附件、工具箱和发送/停止 |
| 消息列表 | `ui/messages` | 按稳定 ID 延迟渲染，Chat 展示 Markdown 子集、思考和工具记录。Image 展示可交互的结果卡片 |
| 会话与生成 | `model` | ConversationSession 更新状态，ChatGenerationRepository 按已保存的供应商、模型和协议选择本机模拟或流式传输。历史文件由后台线程原子写入 |
| 模型与供应商 | `provider` | 供应商、模型和能力声明、Configure、配置编辑、JSON 模板与本地保存 |
| 主题 | `ui/theme` | 纯黑背景、中性灰胶囊控件、字号层级、低对比描边与 H⁺ 标志 |

会话从空白草稿开始，首次发送后才写入历史。一次请求依次经历发送中、生成中和完成，也可以进入已停止或错误。每条回复保存当次模型和参数，切换会话时仍能回到原来的草稿。重新打开应用会进入新的空白会话，已发送过的会话可从侧栏恢复。

## 第一版的设计取值

- 空会话与已有会话的左上角均为两道横杠，点击后打开侧栏。空会话顶部居中选择 Chat 或 Image。已有消息时，左上双行胶囊显示会话名称，下行依次为锁、模式、用量环与数值（例如 0.5k）。点击胶囊可改名。极窄窗口或大字体下，新建入口收进更多菜单。
- 默认采用深色主题与中文界面，保留设计稿中的 Chat、Image、Configure、Done 等标签。设置首页采用居中标题、带分隔线的深灰分组列表和底部搜索框。聚焦搜索时可用右侧关闭按钮退出。
- 顶栏和输入框悬浮在会话上方，滚动时可以从胶囊两侧看到消息。列表顶部和底部按控件的实际高度留出空间，停在首尾时可以读完整条消息。收起键盘后，图片缩略图仍显示在文字上方，可逐张移除。
- 本机 Chat 显示估算用量。Image 独立处理每次请求，手动添加的参考图随该条请求保存。本机模式的示例图由程序绘制。
- 首次启动预设本机对话模型、本机图像模型和 DeepSeek 对话模型。停用聊天供应商后可使用其他可用聊天模型。选中的图像供应商停用时，发送前需要重新选择图像模型或启用原供应商。模型选择面板支持按名称或能力筛选。
- Tools 面板按当前模式展示可用项。Chat 的已启用数量跟随搜索和生图的选择变化，Image 展示参考图张数与配置入口。

## 样式与模型配置

- 首次使用深色纯色样式。用户气泡背景为 `#020562`、边框为 `#030776`、文字为 `#D3F0FF`。助手思考卡与可选正文气泡背景为 `#242628`、边框为 `#3B3F44`、文字为 `#FFFFFF`。浅色方案有独立配色。
- 模型基础页管理输入输出类型、能力和图标。推理页设置可用档位、默认档位和策略。高级页保存本地请求选项，包括 JSON、自定义请求头、单次请求预算和内置工具声明。请求头的值和供应商 API Key 只保留在本次应用进程中。
- 模型编辑与消息样式参考 Kelivo 的页面组织，以本项目的 Kotlin 和 Compose 组件实现。[Kelivo](https://github.com/Chevey339/kelivo)

## GitHub Actions 自动构建

`.github/workflows/android-debug.yml` 在分支推送、拉取请求或手动触发时使用 JDK 17 运行单元测试，构建应用和仪器测试 APK。运行成功后可在该次工作流的 **Artifacts → HydrionHub-debug** 下载应用 APK，保留 14 天。工作流使用 Android 默认调试签名，仓库令牌只读。
